## 2024-10-16 - Prevented DOM-based XSS via innerHTML Replacement
**Vulnerability:** Found multiple instances of \`innerHTML\` being used with template literals in \`extension/content.js\` and \`extension/popup.js\`. While some variables seemed safe, using \`innerHTML\` for dynamic UI injection is a systemic vulnerability risk (DOM-based XSS).
**Learning:** In vanilla JavaScript projects without frameworks like React, dynamically generating UI components requires strict adherence to safe DOM manipulation. Template literals inside \`innerHTML\` can easily introduce XSS if any bound variable contains unsanitized user input.
**Prevention:** Replaced \`innerHTML\` injections of dynamic data with hardcoded static HTML structure containing placeholders (e.g., \`<span id="dynamic-element"></span>\`), followed by targeting the elements using \`querySelector\` and safely updating their values using \`textContent\`. Buttons were explicitly created using \`document.createElement\` to attach handlers securely.
