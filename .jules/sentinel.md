## 2026-08-16 - Prevent Path Traversal in Firebase REST API Calls
**Vulnerability:** Dynamic path parameters (like `roomId` and `userId`) received from untrusted inputs or Chrome messaging payloads were directly interpolated into Firebase Realtime Database REST API fetch URLs (e.g., `https://movieparty-af87f-default-rtdb.firebaseio.com/rooms/${roomId}/lastState.json`) without any validation. This could allow an attacker to craft malicious inputs (e.g., containing `../` or arbitrary strings) to manipulate the database path, leading to unauthorized reads, overwrites, or deletions of critical database structures.
**Learning:** In client-side extensions that interact with Firebase via REST instead of the official SDK, all dynamic path segments in URLs must be strictly sanitized because the HTTP request bypasses the client SDK's internal path validation logic.
**Prevention:** Always validate dynamic path parameters (such as IDs) against an explicit, restrictive regex mask (e.g., `/^[a-zA-Z0-9_-]+$/`) before concatenating them into any URL or database path. Invalid parameters should result in the request being rejected immediately.
