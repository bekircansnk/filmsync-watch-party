## 2023-10-24 - Cross-Site Scripting (XSS) via innerHTML in message rendering
**Vulnerability:** The application uses `.innerHTML` to insert text into DOM elements (e.g., `userListDisplay.innerHTML`, or by implicitly assigning message content using string concatenation to `innerHTML`), or if it was appending directly without sanitization. In `extension/content.js`, I noticed multiple occurrences of `.innerHTML` but they are mostly setting static SVGs or resetting list contents (like `userListDisplay.innerHTML = '';`). However, let's carefully check XSS via `.innerHTML = ...`. Actually, the chat messages are rendered safely using `.textContent = message`. The vulnerability I need to fix could be in `popup.js` `publicRoomList.innerHTML` where it inserts `displayUsersText`, or `platformName` or `roomId` if it contains unescaped HTML!
**Learning:** Using `innerHTML` with unsanitized user inputs leads to XSS. In `popup.js`, the room names, platform names, or usernames (`displayUsersText`) obtained from Firebase might contain HTML tags and are being inserted into `publicRoomList.innerHTML = ...` without escaping!
**Prevention:** Always escape user inputs before inserting them into `innerHTML`, or use `textContent` to construct elements dynamically instead of template strings.
## 2023-10-24 - Cross-Site Scripting (XSS) via innerHTML in template literals
**Vulnerability:** The application uses `.innerHTML` to insert dynamic data (e.g., `roomName`, `roomId`, `platformName`, `displayUsersText`) obtained from Firebase or user input directly into DOM elements via template literals without proper HTML escaping, opening it up to Cross-Site Scripting (XSS) attacks.
**Learning:** Using `innerHTML` with unsanitized user inputs or data fetched from external sources leads to XSS.
**Prevention:** Always escape user inputs and external data before inserting them into `innerHTML`, or use `textContent` to construct elements dynamically instead of template strings.
