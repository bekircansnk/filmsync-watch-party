## 2026-08-06 - Prevent Path Traversal in Firebase REST URL Constructions
**Vulnerability:** When using direct Firebase Realtime Database REST API fetch requests (e.g., PATCH/POST to `.json` endpoints), dynamic path parameters derived from untrusted inputs or Chrome messaging payloads (like `roomId` and `userId`) were concatenated into URLs without validation.
**Learning:** This could allow a malicious user to manipulate the `roomId` or `userId` (e.g., using `../../`) to traverse the database paths and access or overwrite data outside the intended scope. Standard URL encoding does not prevent this if the system subsequently decodes the path, and Firebase paths directly map to the JSON structure.
**Prevention:** All dynamic path parameters used in Firebase REST URL concatenations must be strictly validated against an explicit regex mask (e.g., `/^[a-zA-Z0-9_-]+$/`) before being used. This ensures only safe characters are included, effectively preventing path traversal.
