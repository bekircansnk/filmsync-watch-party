## 2026-10-06 - DOM-based XSS Vulnerability in Template Literals
**Vulnerability:** Found multiple instances where user-controlled variables (e.g., `roomName`, `roomId`, `platformName`) were directly injected into `.innerHTML` using template literals without sanitization in `extension/content.js` and `extension/popup.js`.
**Learning:** Using template literals inside `.innerHTML` assignments is dangerous if any of the interpolated variables are user-controlled, leading to Reflected and Stored XSS risks depending on the data source. Additionally, when using patch scripts to sanitize HTML injections with regex, using a non-greedy match like `[\s\S]*?` will prematurely stop if the template literal contains nested backticks.
**Prevention:** Implement and enforce a standard `escapeHTML` function for all dynamic content injected into the DOM, and ensure the function safely coerces inputs to strings to prevent array-based bypasses. When patching, carefully review template literals for nested backticks before applying regex-based block extraction.
