## 2026-08-12 - Throttling Global Mousemove Events on Video Players
**Learning:** Attaching an unthrottled `mousemove` event to the `document` (e.g., to implement a custom UI auto-hide idle timer) causes substantial main thread overhead due to frequent executions (60+ times per second). In video players specifically, updating the DOM and resetting timeouts repeatedly during cursor movement can trigger reflow overheads, stealing processing time and lowering playback frames. Furthermore, failing to mark global continuous event listeners with `{ passive: true }` forces the browser to wait on the JS thread in case `preventDefault()` is called, blocking default UI responsiveness.
**Action:** Always wrap high-frequency continuous event handlers (like `mousemove`, `scroll`, or `resize`) with a throttle (e.g., 250ms interval) or debounce function to reduce DOM recalculation storms. Additionally, always provide `{ passive: true }` to generic global events so they don't block the browser's default thread tasks.
