## 2024-10-16 - Throttling High-Frequency UI Events
**Learning:** High-frequency events like `mousemove` can cause significant UI lag and jank if not properly throttled, especially when tied to actions like showing a toolbar during full-screen video playback. Implementing a leading-edge throttle is crucial: it executes the action immediately on the first event (providing instant feedback) and then drops subsequent events for the throttle duration. A trailing-edge-only approach (like a standard `setTimeout` debounce) would introduce a perceptible delay, making the UI feel sluggish and unresponsive.
**Action:** When implementing auto-hide toolbars or responding to frequent mouse movements during media playback, always use a leading-edge execution strategy (triggering the action immediately, then ignoring events for the timeout) to maintain immediate responsiveness while reducing performance overhead.
