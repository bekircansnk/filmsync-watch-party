## 2024-10-31 - [Optimize findBestVideoElement calls]
**Learning:** The `findBestVideoElement` function in `extension/content.js` recursively scans the DOM and Shadow DOM to find the video element. This expensive function is called repetitively by `setInterval` loops (like `videoTrackingInterval`, `uiKeeperInterval`, and `iframeKeeperInterval`) and event handlers (`sendMediaEvent`, `handlePageExitNotification`), often bypassing the cached `videoElement` simply to do truthiness checks (`!!findBestVideoElement()`). Attempting to inline a cache check in `setInterval` originally proved less effective than embedding it directly inside `findBestVideoElement` itself, because the unprotected calls still triggered full DOM traversals.
**Action:** When a heavily-used getter performs expensive DOM traversals, always centralize the cache validation directly within the getter function (returning early if the cached element is still valid and connected) rather than relying on inline short-circuits (`videoElement || findBestVideoElement()`) at the call sites, which are easily forgotten or bypassed.
