## 2024-10-10 - Keyboard Navigation on Non-button Interactive Elements
**Learning:** This app uses `span`, `div`, and custom switches as interactive UI elements (like `userAvatarDisplay` and `platform-card`) but misses `role="button"`, `tabindex="0"`, and keyboard event handlers. Users on screen readers or keyboard-only could not engage with critical features (like copying the room code or opening Netflix). Using `keydown` events to simulate `click` on "Enter" or "Space" is essential.
**Action:** When creating custom interactive elements (e.g., custom switches or clickable avatar icons), always apply semantic HTML or add ARIA roles, `tabindex`, and handle `keydown` events matching the default `click` behavior to ensure they remain fully operable via keyboard.
