## 2024-05-24 - Document Firebase Rules Safety
**Vulnerability:** Not an actual vulnerability; Firebase API keys are public by design, but checking for true secrets or overly permissive write access is critical.
**Learning:** Evaluated Firebase configuration inside client-side JS (`extension/content.js`, `extension/popup.js`) and REST requests in `extension/background.js`. Verified Firebase API keys used in JS are public identifiers. The extension accesses `https://movieparty-af87f-default-rtdb.firebaseio.com/rooms...` without any backend API secret/admin token, meaning any user can technically read/write to the DB based on the database rules. Since we don't control the server's Firebase rules from this repository (only client code), there are no hardcoded *secrets* (admin keys) to remove. The API keys found are public Web SDK keys.
**Prevention:** Keep Firebase API keys in client-side code as they are required for Firebase Web SDK and do not grant administrative privileges. Ensure backend database security rules restrict access appropriately.
