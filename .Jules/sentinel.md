## 2024-10-18 - Firebase Database Rules
**Vulnerability:** Firebase Realtime Database rules allow unauthenticated users to read and write to all rooms (`"rooms": { ".read": true, "$roomId": { ".write": true } }`). There is no authentication check (`auth != null`) before allowing these operations, leaving the database vulnerable to unauthorized access and modification. Additionally, Firebase SDK configuration leaks the `apiKey` which is expected, but the lack of rules makes it exploitable.
**Learning:** Realtime Database rules must enforce authentication and authorization. In a watch party extension, users should likely only write to rooms they have joined or created, but at the very least, writes should be restricted, or validated securely. However, given this is an extension without user accounts, a completely open write might be intentional but dangerous. Wait, looking at the rules, there is no `auth` checking at all. Anyone with the config can read all rooms and write to any room.
**Prevention:** Implement strict access control rules using `auth != null` if authentication is used, or validate data aggressively.
## 2024-10-20 - [Fix XSS in Toast Notification]
**Vulnerability:** XSS vulnerability in `extension/content.js` where `targetTitle` was directly injected into `toastBody.innerHTML` using template literals.
**Learning:** Even internal variables like `targetTitle` passed to notification functions can contain user-controlled data (e.g., page titles synced across clients). Directly inserting them into `innerHTML` allows script execution.
**Prevention:** Use DOM manipulation (`document.createElement` and `textContent`) or insert placeholder span elements and assign values via `.textContent` instead of string interpolation for dynamic variables.
