## 2026-09-26 - [High] Fix DOM-based XSS in innerHTML injections
 **Vulnerability:** DOM-based Cross-Site Scripting (XSS). User inputs and data coming from the remote Firebase backend (like roomName, platformName, etc) were being passed directly into DOM elements using `innerHTML` templates in `content.js` and `popup.js` without prior sanitization. This allowed any malicious input in these fields to execute arbitrary JavaScript code inside the browser extension's context.
 **Learning:** Never trust inputs, even if they originate from internal data structures synced with a real-time database. A malicious host could inject payloads through the database which the extension clients blindly render.
 **Prevention:** Always construct UI templates using explicitly sanitized inputs, leveraging a custom `escapeHTML` helper (converting `<`, `>`, `&`, `'`, `"` to HTML entities) when injecting variables into string literals assigned to `innerHTML`. Where possible, prefer the `textContent` property for text nodes over string-based HTML injection.
