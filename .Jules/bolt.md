## 2024-10-20 - Memoizing the Best Video Element Lookup
**Learning:** `findBestVideoElement` heavily relies on `findAllVideosDeep`, traversing the entire DOM and Shadow DOM roots every time it is called. Although CPU optimized, calling this function 14 times throughout the file for every minor operation (like interval ticks or playback toggles) introduces significant unnecessary overhead when the primary video element has already been resolved and remains connected to the DOM.
**Action:** Always short-circuit costly DOM search queries (like `findBestVideoElement` or `findAllVideosDeep`) by caching the resolved target (e.g. `videoElement`) and immediately returning it if it is still `isConnected` and valid. This simple memoization avoids repeated O(N) traversals per tick.
